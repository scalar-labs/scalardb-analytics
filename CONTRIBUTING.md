# Contributing to ScalarDB Analytics

ScalarDB Analytics is maintained by the Scalar Engineering Team.
We welcome bug reports, feature requests, and questions from everyone, but we do not accept code contributions from outside the team yet.

## Code contributions

We do not accept pull requests from external contributors at this time.
Before we can accept a contribution, every contributor needs to sign a Contributor License Agreement (CLA), and the CLA for this project is not ready yet.

We plan to accept code contributions once the CLA is in place.
This document will be updated with the signing process when that happens.
Until then, please open an issue instead of a pull request, so that a maintainer can address the problem or proposal.

## Reporting issues

Open an [issue](https://github.com/scalar-labs/scalardb-analytics/issues/new/choose) to report a bug, propose a feature or an improvement, or point out a documentation problem.
Please search the existing issues first to avoid duplicates.

A bug report is most useful when it includes the ScalarDB Analytics version, the steps to reproduce the problem, and the expected and actual behavior.

## Asking questions

Ask usage questions and start open-ended discussions in [GitHub Discussions](https://github.com/scalar-labs/scalardb-analytics/discussions).
The [ScalarDB Analytics documentation](https://scalardb.scalar-labs.com/docs/latest/scalardb-analytics/design/) may already answer your question.

## Reporting security vulnerabilities

Do not report security vulnerabilities in public issues or discussions.
Follow the instructions in [SECURITY.md](SECURITY.md) instead.

## Code of conduct

Everyone who participates in this project is expected to follow the [Code of Conduct](CODE_OF_CONDUCT.md).
